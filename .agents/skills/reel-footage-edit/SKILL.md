# Reel footage edit

Treat the recorded argument and the creator's latest approved order as the source of truth. A script is a guide; actual speech and usable takes decide the edit. Preserve the complete idea before shortening for pace.

## 1. Inventory and select takes

1. Read the brief, approved script, latest edit notes, and all supplied recordings. Probe duration, dimensions, frame rate, audio, and orientation. Keep source files untouched.
2. Transcribe each recording with source timecodes. Locate every required idea and every alternate take. Build a take log with exact in/out, spoken line, energy, eye line, sound, completeness, and why a take wins or loses.
3. Write a beat checklist before cutting. Include the hook, setup, each level or argument, transitions, technical points, and ending. Mark any line that is unrecorded or only partially recorded. Never imply a missing line was captured.
4. Pick speech at sentence or thought boundaries. Keep the opening and ending specifically approved by the creator. If the user reports a missing or wrong phrase, find the actual source take and correct the timeline.

## 2. Build the narration cut first

1. Make a 1×, narration-only assembly in the agreed order. Keep complete sentences and all essential points even if the first pass exceeds the target duration. Provide a source cut map.
2. Remove false starts, duplicate wording, dead air, and visible looking down or wandering gaze by default. Inspect the neighboring words and frames before each cut; do not use a silence threshold blindly. Cut near quiet points and preserve natural breaths and emphasis.
3. Listen through every join and inspect nearby frames. Use the better take or a visual cutaway when an on-camera jump is distracting. A cutaway must clarify the spoken point, not just conceal a bad join.
4. Share the full-content cut before changing speed or dropping ideas. If faster narration is approved, compare 1× with the requested speed, preserve intelligibility and pitch, then remove remaining pauses. Let the argument set the length; do not force an arbitrary cap.

## 3. Add visuals to the spoken timeline

1. Time B-roll after the narration cut is stable. Use only assets that explain a concept, establish a scenario, or bridge a difficult join. Make vertical framing and safe areas explicit.
2. Reveal chart bars, tiers, and level labels when the matching words are spoken. When a hierarchy builds, show only the levels already introduced. Keep an explanation tag on screen for the full explanation when requested.
3. Start a visual slightly before the associated explanation when it gives the viewer time to read, but do not cover the speaker's reveal with unrelated imagery. Loop short generated clips only where repetition is unobtrusive.
4. Do not add facts or UI cards that the narration never states. Keep text sparse and legible. Avoid top-of-frame text unless the creator asks for it.

## 4. Finish and verify

1. Generate subtitles from the final narration timeline, then correct words, names, and numbers manually. Keep each caption to one or two readable lines; break by phrase, not arbitrary duration. Check caption placement against every chart and overlay.
2. Mix music so it is audible under speech while every word remains clear. Check the intro, quiet phrases, transitions, and ending; avoid normalization that unintentionally lowers both tracks.
3. Deliver an editable project or exact edit decision list, plus the final video. Before handoff, inspect the full export, representative frames, and codec/container metadata. Use the compatibility checklist in [media tools](references/media-tools.md).
4. Record the final source map, speed, pause-removal decisions, visual timings, caption corrections, mix levels, and export settings so revisions can be surgical.
5. Complete `feedback/VIDEO_LEARNING_LOOP.md` for each generated candidate and the final export. Capture the creator's before/after correction, why it mattered, and evidence; carry approved lessons into new prompt versions and regression cases.

Prefer Edits MCP for timeline work and inspection when available. See [media tools](references/media-tools.md) for the connected services and when to use each. Never publish or spend credits without a specific production need and the user's authorization.
