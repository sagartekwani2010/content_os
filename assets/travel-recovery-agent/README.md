# Flight Recovery Agent — recordable Reel prototype

This is a deliberately fictional, 9:16 browser prototype for a Reel. It uses
synthetic traveller data and must never be represented as a deployment at an
airline, travel company, or client.

## What to record

Open `demo.html` at a 9:16 browser viewport, let the automatic run finish,
then tap **Approve recovery plan**. This creates a 7–9 second screen capture:

1. A cancelled flight makes the stakes instantly clear.
2. The recovery agent reads context and calls specific tools.
3. It proposes one recovery path with explicit trade-offs.
4. A guardrail holds the costly action for human approval.

Do not add a generic architecture slide. The interaction itself is the proof.

## Reel frame

**Hook, direct-to-camera (0–3 s):**
“When a flight gets cancelled, the hard part isn’t finding another flight.”

**Demo (3–12 s):**
Screen-record this prototype. Let the decision and human-approval state land.

**Explanation, direct-to-camera (12–22 s):**
“A workflow can fetch a booking. An agent reads the traveller’s actual
constraints, decides which checks matter, and proposes the recovery. But it
doesn’t silently spend money — that is the guardrail.”

**Close (22–27 s):**
“This is where agents earn their complexity: not the happy path, the
exceptions.”

On-screen footer while recording: `Illustrative prototype · synthetic data`.
